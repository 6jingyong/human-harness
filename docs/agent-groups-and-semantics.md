# Human Harness · 双列 Todo 与语义证据交接（2026-11-09）

## 交互

主页改为左右两列纵向列表：Human TodoList 在左，Agent TodoList 在右。点击待办才展开操作。项目与资料仍通过汉堡侧栏访问。

右侧支持两层原生折叠：第一层是模板定义的 Agent（Agent A、Agent B 等）；第二层是任务状态（运行中、待执行、执行失败、等待依赖）。

## 模板中的 Agent 任务归属

Protocol 1.0 向后兼容地加入可选的 agents 定义数组，以及 Agent/script 任务的 agentId。Agent ID 必须已在模板声明；人工任务不能声明 Agent 身份。旧模板没有显式 Agent 分组时，自动归为“默认 Agent”。

示例 document-handoff 已调整为 v1.1.0：资料提取归属 Agent A，最终整理归属 Agent B。

**Agent ID 当前表示任务归属与界面分组，不保证独立模型身份、长期会话或不同执行器凭证。** 任务并行仍由原有项目依赖与 LocalScheduler 判断，而不是根据分组名称决定。

## 带来源的语义记录

Agent 输出新增可选 semanticNotes 列表，每条记录应包含 materialId、sourceArtifactId、sourceRevision、location、summary，可选 caveat。

- 运行器严格核对引用是否属于当前任务授权读取的原件 ID、版本与模板输入；错误引用导致整个运行失败。
- 记录先随候选成果存储，只有产出任务通过人工审核后才成为可复用的项目知识。
- 若原始资料的当前接受版本变化，旧记录自动失去下游注入资格，仍作为历史保留。
- 下游 Agent 只会收到本次任务所需材料对应的已审核记录。
- 项目资料页把结构化语义记录与仅按模板关联的 Agent 报告分开展示。
- 没有 semanticNotes 的旧模型结果继续合法，只是不会自动生成结构化事实。
- 这里保证的是权限、来源引用和审核门槛；**不保证 LLM 提出的事实本身已经正确**。仍需要专业核实。
