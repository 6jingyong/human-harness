# 土地污染调查：项目模板蓝图 v0.1（设计规范，非可执行导入包）

> 本文保留为完整业务需求蓝图，不直接导入运行。对应的简化 **Protocol 1.0 可运行示例** 在 `examples/land-investigation.hh.json`。真实 GIS、点位审定、机构检测及 DOCX 商业报告编制仍需单独接入，不应把示例中的人工确认当作现实专业验收。


## 0. 定位和适用范围

- 用户侧简名：土地污染调查。
- 业务正式名称：建设用地土壤污染状况调查。
- 当前演示项目：此前的地块调查/报告编制工作台，可复用历史影像、企业调查、候选布点、报告写作和规范清洁母版 v2。
- 核心规范参考：HJ 25.1—2019、HJ 25.2—2019、GB 36600—2018、HJ 164—2020，以及生态环境部 2022 年建设用地调查质量控制技术规定（试行）；地方适用规则需按项目地点、时间及调查类型单独核实。
- 此蓝图不能代替实际机构的现场作业、原始采样、实验室检测或专业审核。
- 第一阶段可以经资料、踏勘、访谈及专业判断后结束。仅在结论表明需要进一步采样分析时，进入第二阶段。第二阶段可在初步结果后进一步详细调查。
- 质控措施从方案开始贯穿现场与实验室；相应质控报告/原始记录在工作完成后形成，不是项目初始化资料。

## 1. 模板必须包含的七类定义

用户提出的四部分是产品层的组织方式；实现时拆解为七类明确契约：

1. **初始输入定义**：初始用户 TodoList，项目身份、红线/坐标及用途依据，用户已有的可选资料。
2. **阶段与任务图**：可并行阶段、任务依赖、负责人（人/Agent/脚本/机构）、完成条件、人工审查关口、异常回退。
3. **物料需求目录**：不是现成文件清单，而是每一类“将来可能需要的资料”及其生产来源、激活条件、验收规则、替代或缺失处理。
4. **衍生任务规则**：发现新企业、污染迹象、资料冲突、批准采样方案后，何时生成哪个具体人类任务。
5. **内置资产**：适用的规范索引/通用资料、参考图、调查方法、章节结构、Word母版、可填写模板、配套技能与受信任脚本。内置资产不是本项目证据。
6. **交付契约**：外部正式报告、附件/配图、可追溯辅助成果、内部待办审查清单分别定义格式、审核门禁、来源要求。
7. **版本、证据与验收**：稳定任务ID、章节ID、资料哈希、来源与取得时间、审核人、适用标准版本、变更造成的失效传播。

## 3. 整体工作流与里程碑

| 阶段ID | 核心任务 | 执行者 | 阶段性产物 | 结束门槛 |
| --- | --- | --- | --- | --- |
| S00 intake | 项目初始化、输入材料收件箱与分类 | Human + Script | 项目基础资料、来源索引 | 身份/红线/用途达到可启动要求 |
| S10 scope | 红线解析、坐标与范围核验 | GIS Skill + Human | boundary.geojson、范围图 | 地理边界可核查 |
| S20 history | 历史影像、历史企业/设施、档案、踏勘和访谈整理 | GIS/Research Agent + Human | 历史变化时间轴、候选企业、来源证据 | 污染识别资料覆盖已审核 |
| S30 risk-review | 潜在污染源和风险区域识别、人工确认 | Agent + Human/专业人员 | 审核后的风险区域/判断及不确定项 | 必须完成专业阶段判断 |
| G10 stage1-decision | 判断是否需要采样调查 | Human/专业人员 | 第一阶段专业判断收据 | 选“第一阶段结束”或“进入第二阶段” |
| S40 plan | 土壤/地下水/对照候选点与检测指标、方案 | SamplingPlan Skill + Human/专业人员 | 含逐点理由的方案、变更日志 | 候选点/深度/指标/点位坐标专业审核并冻结 |
| S50 commission | 委托外部采样/钻探/检测及质控工作 | Human + 专业机构 | 委托/任务书、计划、执行节点 | 采样分析方案已冻结后触发 |
| S60 field-lab | 现场采样、样品流转、实验室检测、全过程质控 | 外部专业机构 | 原始采样、检测、质控与相关证明 | 正式成果与对应证据收到并核验 |
| S70 assess | QC、数据一致性与筛选评价、补充采样判断 | Agent + 专业人员 | 受控分析表、评价、追溯与补充调查决策 | QC和数据经过检查，专业结论确认 |
| S80 writing | 按稳定章节ID组织内容、引用图表与证据 | Writer Agent | 待审正文组件/证据映射 | 正式文本由专业人员审核封存 |
| S90 compile | 确定性 Word 排版、图表装配、章节/交叉引用 | Script | DOCX（审阅版）、目录、附件清单 | 引用、格式、来源与附件校验通过 |
| S95 signoff | 专业审核、对外版本签发、必要时评审修改 | Human/专业人员 | 最终签发文档和内部审查记录 | 签发人员确认；评审意见如有须闭环 |

S40-S70 是 G10 判定需进入采样调查后才激活的分支。S80 可以提前起草已经具备证据的章节，S90 对外正式成稿必须经过对应内容门禁。补充调查可从 S70 再次返回 S40，以新方案版本继续。

## 4. 重点：资料需求不等于当前 Todo

一个 material requirement 至少需要：

- material_id、名称、预期内容与格式；
- source_kind：template / user / agent / external_institution；
- required_scope：all / first_stage_only / sampling_branch / conditional；
- visible_when、request_when、due_after、depends_on；
- acceptance：机构/签章与日期、地块/采样点和样品ID一致性、覆盖范围、原始记录、有效性；
- provenance：原件、转录、派生、通用背景资料；
- allowed_resolution：provided / skip_for_now / unavailable / not_applicable；
- invalidates：上游资料改变时需要重新执行的任务/结果。

### 与质控相关的三种不同物料

| ID | 资料/活动 | 何时出现 | 归属 |
| --- | --- | --- | --- |
| M-PLAN-QA | 采样分析方案中的质量保证/质控安排 | S40，采样前 | 方案编制与专业审核 |
| M-FIELD-QC | 现场质控记录、样品流转、现场平行样/空白等适用记录 | S60 现场作业后逐步产生 | 专业机构 |
| M-LAB-QC | 实验室质控原始数据/汇总/质控报告（按适用要求） | S60 取得检测数据及机构质控成果后 | 检测/质控机构 |

此外独立列出 M-DETECTION-REPORT（检测报告）、M-SAMPLING-RECORDS（钻探、建井、采样和送检记录）、M-GEOTECH（已有地勘资料；并非总是新采样的替代品）。

这几类文档**不可互相冒充**。此前案例的地勘11页摘录和质控9页附件是独立资料；质控附件不能充当主检测报告。

### 质控报告的动态触发规则

1. G10 未进入采样分支：质控相关第二阶段资料标为 not_applicable，不生成用户提交任务。
2. S40 未完成点位专业确认：不要求用户委托新勘测，也不要求上传结果。
3. S40 冻结方案：创建 H-050「按批准方案委托专业采样/检测/质控机构并反馈安排」，用户可上传委托/计划与机构信息。
4. S60 委托和工作开始：系统可展示未来需要的现场记录、检测报告、质控资料，但 **H-060“上传实际检测与质控成果”应等机构完成对应交付后才进入当前待办**。可允许机构直接提交到待审收件箱。
5. S60 报告到件：先核验检测报告、质控记录、报告范围与批准的点位/样品ID一致性；不合格则生成“向机构补资料/说明”的用户任务。
6. S70 只有数据和质控材料足够支撑评价且通过专业审查，才允许完成正式结果分析、结论与相应章节。

## 5. 可能衍生的人类任务（不得在启动时堆满清单）

| 触发事件 | 动态生成任务 |
| --- | --- |
| GIS/企业调查提出候选风险企业，证据不充分 | 向政府/企业索取历史经营、环评或排污资料 |
| 已识别疑似污染设施 | 人工确认设施位置及对应证据；候选不直接写正式结论 |
| 历史影像/采访记录冲突 | 请提供可证实的原件，或记录无法取得 |
| 生成候选风险区 | 用户对风险区 retain_candidate/defer_location/exclude_candidate，保留理由和日志 |
| 生成候选布点 | 用户在地图移动/增删/备注、确认检测指标和采样深度，专业审核 |
| 点位方案被冻结且批准采样 | 委托机构执行采样、钻探、检测与质控 |
| 机构完成现场与实验室工作 | 收取正式检测、现场和质控材料 |
| 检测结果/质控异常 | 调查机构解释、机构复核或补充调查及重新采样决策 |
| 形成待审正文 | 逐章节专业审核与必要的补料任务 |
| 收到评审意见 | 建立逐条修改/补证据/重新审核的任务 |

所有候选发现集合必须先去重、审核、冻结为确定集合，再逐个生成资料需求。用户已提交对应材料时应自动满足同类需求，不重复询问。

## 6. 内置模板、资料和自动化资产

### 内置参考资料（只能用作通用方法和背景）

- 国家标准与地方适用规范索引（版本/来源/适用时间与地区），不能将旧版标准默认为现行；
- 地块历史调查方法、企业调查及访谈方法、风险识别与采样布点说明；
- 调查技术路线图、章节依据映射、分析/质控规范组件。

### 内置的可填写母版

- 《土地污染调查报告》稳定章节树（既有第1—7章工作稿作迁移起点，不自动等同唯一法定目录）；
- 规范清洁母版 v2，用于成稿阶段排版和检查，**不作为正文事实写作输入**；
- 企业/历史影像调查记录表、现场踏勘/访谈记录表、点位方案、布点说明、质控完整性核查表、待办核查清单；
- 附图、表格、封面、目录、图注、附件索引模板。

### 内置技能与受控脚本

- 红线解析、投影转换、地块范围/空间叠图；
- 历史影像（Google Earth）与企业候选调查、地图落点和人机审核；任何截图需带真实来源与时间；
- SamplingPlan 候选生成与逐点解释、地图审核、变更后约束检查；
- 文件分类、OCR/文本识读、证据索引、表格提取、文档版本和校验哈希；
- 章节写作器、事实/依据映射、独立核查清单；
- 确定性 DOCX 装配、目录编号与交叉引用、图表排版和导出验证。

不是所有技能都已经迁入 Human Harness；在模板里必须标注 implemented / reusable_external / planned，绝不能仅因模板声明就称其可执行。

## 7. 输出契约

### 正式对外交付

- 经过专业确认的土地污染调查报告（DOCX 为可编辑原稿；PDF 仅在真实生成后提供）。
- 报告内图、表和必要附件，来源可追溯。
- 报告正文仅纳入足以支持的项目事实、调查过程、检测与质控评价、专业判断及结论建议；不把“请核查原件”“待用户补料”之类内部指令写入商业报告。
- 若走第一阶段结束路线，则不自动生成第二阶段的采样、检测或质控结果章节的虚构内容。
- 若走采样路线，检测/质控完整性和专业审核属于结果章节和最终签发的门禁。

### 内部交付（分开保存）

- 编制核查事项清单/用户下一步Todo；
- 按阶段保存的候选企业、风险区和布点方案、专业审核决定与修改历史；
- 原始证据、结构化摘录、图像、来源哈希、版本收据；
- 程序执行日志、验收结果与未闭环问题。

验收不是“文件存在就通过”：要检查证据映射、点位/样品ID、统计评价、质控、附件、章节结构与人类签发。

## 8. Human Harness 所需新增核心机制

1. **MaterialRequirement（资料需求规范）** 与 MaterialArtifact（真实文件）分离；
2. **ActivationRule（激活规则）**：初始/阶段依赖/事件条件/人工审核后触发；
3. **DecisionGate（专业决策关口）**：第一阶段结束、进入采样、采样点位冻结、异常补充调查、正式签发；
4. **TaskProjection（待办投影）**：按当前可行动作展示用户列表，而非把未来全部可能需求列入当前列表；
5. **PackageAssetRegistry**：可版本化的参考资料、母版与受信任脚本；
6. **DeliverableContract**：交付格式、实际生成器、内容与证据校验、责任人；
7. **InvalidationGraph**：红线变化重做GIS/历史调查；点位变化失效采样委托与对应结果；检测数据修订触发结果评价与结论重审；
8. **Inbox & Triage**：任意阶段可上传新材料，先 needs_triage，按事实归类、去重、匹配 MaterialRequirement 后触发下一步。

## 9. 三个最重要的验收回放

A. 新地块只上传红线、项目身份和用途依据：历史调查自动推进，用户列表**不出现**新采样检测报告/质控报告。

B. 候选风险区和采样点完成专业审核后：系统生成委托任务；机构实际完成工作并提供对应材料后，系统才激活接收/核对正式质控和检测成果的任务，并要求结果与点位对应。

C. 第一阶段判断无需采样：系统应直接走第一阶段报告/签发路径；第二阶段质控报告被标记 not_applicable，而非“缺料导致永久卡住”。

## 10. 当前实现边界

本文件是 **Human Harness 未来土地污染调查项目包的详细规格**，不是当前 v2 JSON 导入器能够直接运行的模板。

当前 v2 支持静态 stages、tasks、文字资产、受控脚本ID和单文件文本输出合同；尚不支持条件分支、MaterialRequirement、动态用户任务、专业门禁及 Word/PDF 成稿。下一阶段需先改引擎/Schema，再将此蓝图编译为可运行模板。
