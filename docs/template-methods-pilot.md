# Human Harness · 项目模板方法与三 Agent 业务闭环（2026-11-09）

## 结论与边界

**资料理解和提取方法属于项目模板；Human Harness 只执行权限、依赖、版本、方法检查项的格式/引用约束和人类审核闸门。** 平台没有内置行业语义引擎，也不会把模型自称“通过”当作客观正确。

本轮新增一个可选、向后兼容的模板方法层，并安装了示例模板 **`technical-spec-review`（双来源技术规格核对）**。沿用原有左右双列 Human/Agent Todo、Agent 分组和材料资料库。

## 1. 模板方法结构

对 `materials[]` 可选定义 `method`：

- `acquisition`：从哪里、由谁取得原始资料；
- `extraction`：要提取哪些字段及其引用形式；
- `verification[]`：需核对的来源、版本、单位与逻辑事项。

对 Agent/script `steps[]` 可选定义 `method`：

- `procedure[]`：本步骤按什么顺序处理；
- `checks[]`：稳定 `id + criterion` 的逐项检查；
- `onMissing`：`request_human`（按步骤已授权的材料 ID 发 Human Todo）或 `record_limitation`（记录限制，不得随意发问）。

未配置此方法结构的旧模板行为保持兼容。模板经项目创建后作为快照固定，不因后续模板更新静默改变项目。

## 2. 方法在真实执行链中的作用

每个 Agent WorkItem 只收到**当前步骤**的方法和被授权资料的方法，不公开其他步骤、其他资料的操作提示。

当模型或 Skill 返回完成候选结果时，如果模板定义了检查项，`methodChecks[]` 必须恰好覆盖全部检查 ID，不允许缺项、重复或杜撰检查项。每项具有：

- `checkId`；
- `status`：`passed` / `failed` / `unverified`；
- `explanation`；
- `evidenceRefs[]`：必须属于本次授权的原件或已审核上游成果。存在授权输入且宣称 `passed` 时至少提供一个引用。

未授权引用、缺项和非法结果在进入审核阶段前被拒绝。需要补资料时允许先转 Human Todo，不强迫模型制造“已完成”检查项。

这些都是 **Agent 自检结果**，不会自动解除人工审核。Human Todo 中会列出检查项、状态和说明；如果包含 `failed/unverified`，人工批准必须填写明确理由。Demo 模式所有检查均报告 `unverified`，不可伪称实际解析通过。

## 3. 多 Agent 业务验证样例

已安装模板：`examples/technical-spec-review.hh.json`。

样例以采购需求与供应商规格不一致为条件，使用测试文本：

- 需求方：额定电压 **220 V**，功率 **7.5 kW**；
- 供应商：额定电压 **380 V**，功率 **7.5 kW**，原始规格版次缺失。

任务流：

1. Agent A 单独提取需求，Agent B 单独提取供应商规格，两者可同时执行；互不授权读取对方原件。
2. Agent B 请求人类确认版次；Human Todo 回答后，B 恢复执行，并对未获正式证明的版次标记 `unverified`。
3. 用户审核两份候选成果，对未核实版次批准时必须写明例外处理理由；再由独立 Human Todo 记录两者电压冲突的处理意见。
4. Agent C 接收两份已批准的 Agent 中间成果、两份当期原件以及人类冲突处理意见，形成有证据与限制边界的最终候选说明。仍需人类签收。

测试 `tests/template-methods.test.ts` 使用固定业务样例和**受控执行器**，验证以上依赖、隔离、异常分支和审核逻辑；不是对真实供应商或 Codex 模型的事实验证。此前已存在的 Codex app-server 协议 fixture 也测试了材料请求和结构化检查返回，但不调用真实模型。

## 4. 后续路线

首要目标是拿一份用户提供的、真实但可公开/脱敏的工作资料，通过同一个三方流程做一次**实物验收**，并确认文档 Skill 产生的引用能被审核人员复核。

不建议现在开发复杂流程 DSL、自研解析器或多个长期 Agent 会话。模板方法当前保持最简可读的结构化描述；确有真实需求再扩充为可执行 Skill 绑定和确定性自动校验。

## 当前限制

- 对方法检查的`passed`校验只保证字段、来源作用域与模板 ID 一致，不保证专业结论客观正确。
- 任一 Agent 可报告 `unverified`，需人工批准/退回。拒绝后由原来工作流重做，不自动更改模板。
- Codex 真实认证调用、PDF/DOCX Skill 实际提取与生产部署仍未在本轮运行；CI 浏览器使用 Demo 和可控样例。
