# 环评 A→B→C 故意污染试验：阶段隔离验收（2026-11-09）

## 正确的测试目标

**这是功能正向测试，不是要让 Human Harness 自动判断内容正确。**

用户要求三个 Agent 只完成各自职责：

- **A：资料 → 结果**。A 只能用模板授权的原始资料及已有半成品，产出结果；即使故意输出一份无关菜谱 JSON，格式和模板契约满足的候选仍可被提交审核。
- **B：已审核结果 → 分析结论**。B 不重新读取原件，也不回头执行 A 的工作；当 A 的无关结果被人为批准后，B 应当**确实收到**该结果，并可故意从土豆菜谱推导出荒谬结论。
- **C：已审核结论 → 最终文件**。C 只能读取 B 的已审结论及人工交接，不直接读取 A 的 JSON 或原件。B 的荒谬结论被人为批准后，C 可以把它写入最终文件。最终人工批准后，这份内容错误的文件应**确实可以下载**。

也就是说，测试故意将错误注入每一级，观察流程是否不越权、不擅自纠错或重复读取上游输入。**错误能够按已获授权的数据交接传播，正是本次隔离功能的预期结果。**

## 两类场景各自验收什么

| 场景 | 操作 | 预期行为 |
| --- | --- | --- |
| **不批准** | A 故意提交无关 JSON，B 故意产出胡扯结论；操作员选择退回重做 | 未批准的候选不得进入下一阶段；下游暂停；退回意见交给原 Agent；新的批准版本替换旧候选的下游输入；历史保留。 |
| **故意批准** | 操作员批准 A 的菜谱 JSON，批准 B 的荒谬结论，再批准 C 的受污染文件 | B 仅收到 A 已批准结果；C 仅收到 B 已批准结论；文件能够实际下载，且内容保留预先植入的错误标记。**这是通过，不是失败。** |

其中“批准”是人类交接许可和流程状态，而非一套独立事实真伪证明。Human Harness 不会仅凭其本身的判断把错误事实改成正确事实。

## 验证证据和边界

测试：`tests/eia-adversarial-pipeline.test.ts`。

关键断言：
1. B 看到的唯一证据是 `approved_derived` 的 `enterprise-results.json`，包含 `UNRELATED_A_PAYLOAD`，不包含任何直接原件。
2. C 仅看到 `enterprise-conclusion.md`、`qc-conclusion.md` 两份已批准 B 结论，**没有**原始 PDF、Word 或 A 阶段 JSON。
3. C 生成的候选包含 `POISONED_C_CANDIDATE`；最终签收前下载返回 409，人工签收后下载返回 200，文件正文仍包含该标记。
4. 退回重做的独立场景验证了不会把已退回的 A/B 候选误传给后续步骤。

以上为**受控执行器和固定恶意样例**的功能测试，不是说真实模型必然忠实遵循这些边界。真实模型执行仍需使用相同的输入作用域及结果交接测试。

## 设计结论

- 默认保持 **A→B→C 处理职责隔离**，绝不为了发现内容荒谬让 B 重新阅读 A 的原件，或让 C 重新运行 A/B 的推理。
- 如果某个项目希望增加核验，则在项目模板中**明确安排属于相应阶段的审核责任**，而非偷偷把全链路检查塞进每个 Agent。
- 结构/契约检查和任务授权是引擎职责；具体事实是否成立，属于模板指定的业务处理和用户审核责任。
- 同一分支 A→B→C 依赖顺序不变；多个分支仍可以流水线并行。

**不把“污染成功”当作通用事实可靠性结论；它只证明人机工作台的数据路由和任务边界按预期运转。**
